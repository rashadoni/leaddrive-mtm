# SwissMed → LeadDrive MTM: фармацевтические parity gaps

**Статус документа:** канонический продуктовый контракт для `leaddrive-mtm`.
**Источник:** все 18 переданных фотографий SwissMed / QuadraSoft CRM 3.1.
**Клиенты:** фармацевтические полевые агенты, их менеджеры и администраторы.
**Устройства:** Android-планшет в первую очередь, смартфон — обязательный адаптив.

Этот документ дополняет `swissmed-parity-register.md` и сохраняет все предметные
требования, найденные при детальном screen-by-screen аудите. Шестнадцать GAP ниже —
это пакеты реализации; они покрывают все 18 фотографий, поэтому их количество не
обязано совпадать с количеством снимков.

## Граница продукта

- LeadDrive MTM владеет врачами, фармацевтами, клиниками и аптеками, назначениями
  агентов, планами, маршрутами, визитами, GPS, задачами, промо, KPI и полевыми
  доказательствами.
- LeadShelf — отдельный проект. Планограммы, полки, facings, оборудование и
  shelf-аналитика не входят в это приложение и не являются зависимостью MTM.
- MTM может хранить только внешние идентификаторы бренда/продукта и снимок
  отображаемого названия. Недоступность другого продукта не блокирует маршрут,
  визит, задачу или промо MTM.

## Роли и правила готовности

- **Agent:** работает со своей назначенной базой, планом, визитами, GPS, задачами,
  промо и полевыми оценками; потенциально спорные изменения отправляет на проверку.
- **Manager/Supervisor:** назначает базу, публикует планы, проверяет изменения,
  отмены, задачи, промо и GPS, анализирует командные KPI.
- **Admin:** управляет справочниками, территориями, формулами, политиками и аудитом.
- Скрытая кнопка не считается RBAC: каждое действие проверяется сервером в tenant
  scope, имеет idempotency и audit event.
- Статус «готово» требует рабочего UI, API, разрешений, RU/AZ/EN, офлайн-пути там,
  где он нужен агенту, тестов и acceptance по соответствующей фотографии.

## Текущее подтверждённое основание

На `leaddrive-mtm` уже существуют: role-safe навигация, настраиваемая главная,
авторитетный рабочий день, офлайн-чтение маршрутов/задач/контактов, durable task
mutations, визитный workspace, недельная agenda, GPS history list, реальные Manager
planning/approvals, каталоги и карточки организаций/контактов, а также расширенный
task detail (timeline, edit, recurrence, duplicate, progress, return/review,
due-date quick set, bulk reassign, files read).

Это основание нельзя выдавать за полный SwissMed parity: большинство пакетов ниже
ещё частичны.

## GAP-001 — Массовая передача «Моих контактов»

**Связь со снимками:** SWM-02, SWM-05. **Роли:** Manager/Admin.

- Мультивыбор контактов, текущий ответственный и выбор нового агента.
- Preview до подтверждения: scope, неактивные сотрудники, конфликты открытых
  визитов/планов, исключённые записи.
- Effective-dated смена `MtmContactAgentAssignment`; история не перезаписывается.
- Атомарная и идемпотентная операция, причина, actor/time, audit и результат.
- После sync записи исчезают у Agent A и появляются у Agent B без потери истории.

## GAP-002 — Управление «Моими организациями»

**Связь:** SWM-01, SWM-02, SWM-07, SWM-08. **Роли:** Agent read; Manager/Admin manage.

- География: область/регион, административный район, населённый пункт, район города.
- Классификация: категория, специализация, тип, вид, статус, территория, полигон.
- Управляющий менеджер, назначенный сотрудник, свободные организации.
- Поиск, server pagination, saved views, configurable columns и bulk assignment.
- На телефоне — карточки и bottom-sheet фильтров; на планшете — list/detail и
  управляемая таблица. Агент офлайн видит только свой опубликованный scope.

## GAP-003 — Полная карточка и форма контакта

**Связь:** SWM-03, SWM-05. **Роли:** Agent read/request; Manager/Admin edit.

- Несколько мест работы: клиника/аптека, отделение, должность, primary, даты действия.
- Фамилия, имя, отчество, дата рождения, пол, специальность, квалификационная
  категория, профиль, должность и примечания.
- Рабочий, домашний, мобильный телефоны; Viber/WhatsApp/Telegram; email.
- Домашний адрес: индекс, область, населённый пункт, район, улица/дом.
- Категория по товарам и категории/потенциал по брендам.
- Верификация, дубликаты, consent/contact preference, source и change history.
- Агентские правки могут переходить в `PENDING_REVIEW`, а не менять master-data
  без контроля.

**Реализация GAP-003:** полный responsive contact detail/edit для телефона и
планшета; direct Manager/Admin mutation и отдельная idempotent Agent review queue;
effective-dated workplace history; поиск/сообщение о дубле; audit trail; полный
Agent-scoped offline snapshot. Фармацевтический scoring, per-brand строки и единый
relationship timeline намеренно остаются в GAP-004, GAP-005 и GAP-006, а не
маскируются внутри этой главы.

## GAP-004 — Фармацевтический скоринг врача

**Связь:** SWM-04. **Роли:** Agent observe; Manager validate; Admin configure.

- Кабинет, пациентов в месяц, койко-места, KOL/лидер и уровень KOL.
- Профиль, психотип и гранулярная категория врача (например B2, не только A–D).
- Баллы факт/цель с источником, периодом и версией формулы.
- Пока формула не подписана, мобильное приложение не вычисляет баллы само:
  сохраняется введённое/полученное значение, provenance и статус проверки.
- Все оценки effective-dated; новая оценка не уничтожает предыдущую.

## GAP-005 — Потенциал и раскрытие по брендам

**Связь:** SWM-04. **Роли:** Agent record; Manager validate.

- Таблица: сотрудник, бренд/продукт, потенциал, раскрытие/coverage, категория,
  период, источник и проверка.
- Потенциал поддерживает измерение по врачу × агенту × бренду, если это разрешено
  tenant-политикой.
- Добавить, изменить, завершить период, показать историю и перейти к визитам,
  подтверждающим оценку.
- MTM хранит внешний brand/product ID и snapshot имени; планограммы не подключаются.

## GAP-006 — История взаимоотношений

**Связь:** SWM-03, SWM-04, SWM-06.

- Единый timeline по контакту/организации: визиты, задачи, обязательства, сообщения,
  промо и изменения master-data.
- Сервер агрегирует существующие сущности с пагинацией и tenant scope; отдельная
  дублирующая модель истории не нужна.
- Каждая строка открывает исходную сущность и показывает actor/time/status/evidence.

## GAP-007 — «Мои контакты» и принадлежность

**Связь:** SWM-05.

- Фильтры: сотрудник, география, организация, ФИО/телефон, специальность, профиль,
  категория, психотип, Target/MOI, потенциал и статус.
- Добавление/снятие контакта из назначенной базы, одиночное и массовое.
- Last visit, next planned visit, visits this month и coverage context.
- Offline-first Agent list; Manager видит сотрудников своей команды.

## GAP-008 — Психотип

**Связь:** SWM-04, SWM-05, SWM-16.

- Tenant-scoped локализованный справочник психотипов с active period и audit.
- Поле в карточке врача, фильтр в контактах и планировании.
- Значение не hard-code и не свободный текст без справочника.

## GAP-009 — Полная карточка организации/клиники/аптеки

**Связь:** SWM-01, SWM-06, SWM-07.

- Реквизиты, код/Etalon ID, тип/вид/категория/статус, адрес и подтверждённые GPS.
- Контакты, отделения, персонал, визиты, задачи, промо, файлы и история.
- Территория, полигон, ответственные сотрудники, last/next visit и coverage.
- Создание/правка Manager; Agent создаёт расширенный запрос с последующим review.

## GAP-010 — Target/MOI, последнее посещение и частота

**Связь:** SWM-04, SWM-05, SWM-13, SWM-15, SWM-16, SWM-18.

- Target/MOI являются tenant-configured effective-dated признаками/категориями.
- В каталогах и планировании показываются last visit, visits this month,
  required frequency, overdue/coverage state и источник расчёта.
- Любой KPI drill-down ведёт к точным контактам и визитам.

## GAP-011 — Промо для аптек и врачей

**Связь:** SWM-09. **Роли:** Agent execute; Manager L1/L2 review.

- Кампания, тип акции, организация/контакт, бренд/продукт, период и условия.
- План/факт, количество, сумма, баллы, призы, фото/файлы и комментарии.
- Статусы выполнения, отправки, возврата, L1/L2 проверки и закрытия.
- Баллы рассчитываются только серверной versioned формулой с numerator/source
  drill-down; до утверждения формулы показывается `UNCONFIGURED`, а не фиктивный 0.
- Офлайн Agent submission имеет idempotency, media retry и conflict UI.

## GAP-012 — GPS history, route replay и live team map

**Связь:** SWM-10, SWM-11, SWM-12.

- Agent self-history; Manager — только scoped team members.
- Дата/время, точность, батарея, online/stale, дистанция и обнаруженные остановки.
- Planned route, actual polyline, visits/check-in/out, stops и data gaps.
- Plan-vs-fact, skipped-point reason и переход к evidence визита.
- Карта реализуется через provider abstraction. Без ключа/тайлов остаются рабочими
  list/timeline/replay data; native rendering проходит отдельный physical-device gate.

## GAP-013 — KPI агента и Manager BI

**Связь:** SWM-13, SWM-15.

- Личный KPI: week/month с явно указанным периодом, timezone и freshness.
- План/факт визитов, GPS-confirmed %, покрытие врачей/аптек, Target/MOI,
  задачи, промо и distance/workday quality.
- Manager: department/team/agent, visit type, brand/product и period filters;
  тренд по месяцам/кварталам.
- Каждый показатель раскрывает numerator, denominator, exclusions, formula version
  и source records. Mobile не пересчитывает серверные формулы локально.

## GAP-014 — Полная задача

**Связь:** SWM-14.

Уже реализованные lifecycle, recurrence, duplicate, progress, review/return,
due-date quick set, bulk reassign, timeline и files-read сохраняются. Осталось:

- группа/категория задачи;
- мероприятие/кампания;
- отдельные `scheduledStartAt` и `dueAt`;
- точный date/time picker и `recurrenceUntil`;
- upload/camera evidence с durable media outbox;
- физический Android gate для камеры/date picker.

## GAP-015 — Home фармацевтического агента

**Связь:** SWM-15, SWM-17.

- Настраиваемые 1–6 виджетов сохраняются: один занимает workspace, два делят его
  поровну, остальные образуют равномерную адаптивную сетку.
- Ключевое закреплённое сообщение/анонс.
- Покрытие Аптеки/Врачи/Всего: required, Target covered, actual, uncovered.
- Отменённые визиты, требующие подтверждения Agent, и активные задачи.
- План недели с началом дня, план/факт и быстрым переходом к визиту/задаче.
- Focused widget открывает функциональный drill-down, а не увеличенную статичную карточку.

## GAP-016 — Планирование «контакт × день»

**Связь:** SWM-16, SWM-17, SWM-18. **Роли:** Manager publish; Agent acknowledge/request.

- Направление Врачи/Аптеки; горизонт 5/7 дней и месяц.
- Фильтры по географии, организации, специальности, психотипу, категории,
  Target/MOI, last visit, frequency и potential.
- Контакт × день, select/unselect cell, row/day bulk actions, monthly visit count.
- Capacity, leave/non-working day, duplicate time, scope, joint-visit и route conflicts.
- `DRAFT → VALIDATED → PUBLISHED → ACKNOWLEDGED`; изменение опубликованного плана
  создаёт новую версию. Agent может запросить изменение/отмену.
- На планшете — sticky identity + горизонтальные даты; на телефоне — contact-first
  карточка с рядом кнопок дней, не сжатая desktop-таблица.
- Published near-term plan и route доступны Agent offline.

## Порядок реализации

1. **Безопасность/offline:** durable visit/check-in/task/media mutations, conflict UI,
   cache consumption, tenant/user isolation и видимый sync status.
2. **Управляемые каталоги:** GAP-001/002/007 и общие фильтры/assignment components.
3. **Карточки:** GAP-003/009, затем психотип/Target/last visit (GAP-008/010).
4. **Фармацевтический профиль:** GAP-004/005/006.
5. **Планирование и Home:** GAP-016 → GAP-015.
6. **GPS/карты:** GAP-012 с list-first fallback и physical-device gate.
7. **KPI:** GAP-013 после утверждения формул и эталонного набора данных.
8. **Промо:** GAP-011 после утверждения формулы баллов; без зависимости от LeadShelf.
9. **Release:** RU/AZ/EN, accessibility, emulator + physical tablet/phone,
   signed APK/AAB, PR → merge → CI. `deploy.sh` вручную не запускается.

## Acceptance baseline

Для каждого GAP обязателен тест, который начинается с соответствующей фотографии
и заканчивается проверяемым результатом в LeadDrive MTM. Нельзя закрывать GAP по
наличию таблицы Prisma, API-заготовки, preview-widget или happy path без офлайна,
scope, audit и error/conflict states.
